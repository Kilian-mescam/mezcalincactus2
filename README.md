# Mezcal In Cactus — site vitrine statique

Ce projet est une application React + Vite destinée à présenter un groupe de musique, avec :
- une landing page publique,
- une section Tour alimentée depuis Supabase au runtime,
- une mini galerie de photos et vidéos YouTube,
- une section Bio, Shop et Footer,
- un back-office /admin protégé par Supabase Auth.

## Configuration Supabase

1. Créez un projet Supabase sur https://supabase.com.
2. Dans le Dashboard, ouvrez SQL Editor.
3. Exécutez le script dans `supabase/concerts.sql`.
4. Copiez les valeurs du projet dans `.env` à partir de `.env.example` :

```bash
cp .env.example .env
```

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

> La clé anon est publique et sert à lire les données autorisées par le RLS. Les écritures restent protégées par l’authentification Supabase.

## Créer le compte admin

1. Allez dans votre projet Supabase.
2. Ouvrez `Authentication > Users`.
3. Créez un utilisateur avec l’email et le mot de passe de l’admin.
4. Connectez-vous ensuite sur `/admin` avec ce compte.
5. Le compte est admin uniquement si l’utilisateur est authentifié. Les politiques SQL limitent les écritures aux utilisateurs authentifiés.

## SQL de création de la table et policies RLS

Voir `supabase/concerts.sql`.

### Table

```sql
create table public.concerts (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  date timestamptz not null,
  ville text not null,
  salle text not null,
  url_billetterie text null,
  complet boolean not null default false
);
```

### Policies

```sql
alter table public.concerts enable row level security;

create policy "Public can view concerts"
on public.concerts
for select
using (true);

create policy "Authenticated users can insert concerts"
on public.concerts
for insert
with check (auth.role() = 'authenticated');

create policy "Authenticated users can update concerts"
on public.concerts
for update
using (auth.role() = 'authenticated')
with check (auth.role() = 'authenticated');

create policy "Authenticated users can delete concerts"
on public.concerts
for delete
using (auth.role() = 'authenticated');
```

## Modifier les données statiques

- `src/data/config.js` : nom du groupe, tagline, liens réseaux et `shopUrl`.
- `src/data/gallery.js` : images et IDs YouTube en embed.
- `src/data/bio.js` : texte et photo de présentation.

Si `shopUrl` est vide, le site affiche le message : "Boutique bientôt disponible".

## Démarrer en local

```bash
npm install
npm run dev
```

Le site est ensuite disponible sur http://localhost:5173.

## Builder / build de production

```bash
npm run build
```

Le dossier `dist/` est prêt pour un déploiement statique.

## Déploiement statique

### Netlify

1. Importez le dépôt GitHub.
2. Choisissez le framework Vite.
3. Réglez le build command : `npm run build`
4. Réglez le publish directory : `dist`
5. Ajoutez les variables d’environnement :
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

### Vercel

1. Importez le projet.
2. Utilisez le framework preset Vite.
3. Ajoutez les variables d’environnement dans le dashboard.
4. Déployez ; le site est statique et charge les données en runtime depuis Supabase.

## Bonnes pratiques

- Gardez la clé anon publique, c’est la clé destinées au client.
- Les écritures passent par l’authentification Supabase + policies RLS.
- Les données de concert peuvent être modifiées sans redéploiement du front.
